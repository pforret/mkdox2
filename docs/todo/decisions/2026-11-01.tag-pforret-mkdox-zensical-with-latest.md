# Tag pforret/mkdox-zensical with :latest + the Zensical version

## Context
While planning the Zensical image update (0.0.24 → 0.0.74), the question was how `docker/push_docker.sh` should tag `pforret/mkdox-zensical`. Until now only `:latest` was pushed, although CLAUDE.md said the image shares the repo `VERSION.md`.

## Options considered
- `:latest` + Zensical version (e.g. `:0.0.74`): the tag says what is inside the image and users can pin with `-D pforret/mkdox-zensical:0.0.74`; it doesn't say which mkdox release it goes with.
- `:latest` + repo `VERSION.md` (e.g. `:2.1.2`): ties the image to a mkdox release, but bumping Zensical without bumping the repo would overwrite an existing tag.
- Only `:latest`: simplest, but users can't pin and can't see the Zensical version.

## Decision
Tag pforret/mkdox-zensical with :latest + the Zensical version

## Consequences
Image tags follow Zensical releases, independently of the mkdox version. `push_docker.sh` reads the version from the `FROM zensical/zensical:<x.y.z>` line, so bumping Zensical is a one-line Dockerfile change. CLAUDE.md must no longer claim the image shares `VERSION.md`.
