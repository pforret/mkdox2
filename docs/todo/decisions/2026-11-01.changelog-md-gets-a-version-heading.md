# CHANGELOG.md gets a version heading for each tagged release; new changes go under a fresh [Unreleased]

## Context
The item only asked for a CHANGELOG line for the `IO:die` fix. But v2.2.0 had just been tagged and released (commit f862966, setver) while all its changes were still under `## [Unreleased]`, so a new entry would have been mixed in with released changes.

## Options considered
- Add the line under the existing Unreleased (spec): the released and unreleased changes get mixed.
- Rename that block to `## [2.2.0] - 2026-11-01` (matching the tag), move the CI line into it (it shipped in v2.2.0), and start a new `## [Unreleased]`: the CHANGELOG matches the tags.

## Decision
CHANGELOG.md gets a version heading for each tagged release; new changes go under a fresh [Unreleased]

## Consequences
Keep a Changelog structure: one `## [x.y.z] - date` per tag. setver doesn't do this, so at release time (or `/fodo:commit`) rename `[Unreleased]` to the new version.
