# {SITE_URL} is the bare host name; templates write site_url = 'https://{SITE_URL}/'

## Context
The with_blog item made mkdox2.sh fill `{SITE_URL}` with `https://<name>.test/`, and only with_blog was tested. While building all 6 templates for the plugins item, the other 5 turned out to have `site_url = "http://{SITE_URL}"`, giving `http://https://d_simple.test/`, which broke 404-page asset URLs (privacy warnings). Page content also uses `{SITE_URL}` as a host name (`https://staging.{SITE_URL}`, `noreply@{SITE_URL}`, `committee@{SITE_URL}`).

## Options considered
- Keep `https://…/` in `{SITE_URL}` and fix every place that uses it: changes the meaning of a placeholder that content depends on.
- `{SITE_URL}` = bare host name (as before), and all 6 `zensical.toml` say `site_url = "https://{SITE_URL}/"`: one consistent pattern; content keeps working.

## Decision
{SITE_URL} is the bare host name; templates write site_url = 'https://{SITE_URL}/'

## Consequences
mkdox2.sh passes `-v SITE_URL="$site_name"` (e.g. `demo.test`). The scheme and trailing slash live in each template's `site_url`. New templates must write `site_url = "https://{SITE_URL}/"`; in page content `{SITE_URL}` is a host name.
