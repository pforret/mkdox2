# The error trap keeps the original exit status; IO:die called directly exits with 1

## Context
Fixing `IO:die` (it always exited 0 via `Script:exit`). The item left open whether the INT/TERM/EXIT trap, which calls `IO:die` with the failing `$?` in its message, should exit with that original status or always with 1. Decided by default during implementation, since it is low-stakes and reversible.

## Options considered
- Always 1: simplest; the trap would turn a plain `exit 0` that bypasses `Script:exit` into a failure.
- Keep the original status: the trap stores `__trap_exit_code=$?` and `IO:die` exits with it (direct calls: 1). A stray `exit 0` stays a success, real errors keep their code (e.g. an unbound variable → 1).

## Decision
The error trap keeps the original exit status; IO:die called directly exits with 1

## Consequences
`Script:exit [status]` (default 0) is the single exit point; `IO:die` exits with `${__trap_exit_code:-1}`. Don't use plain `exit` in mkdox2.sh; use `Script:exit <n>` so the trap is cleared. The bashew upstream template (pforret/bashew) still has the old behaviour.
