# mkdox2 new fills site_url with https://<name>.test/

## Context
`mkdox2 new` filled `{SITE_URL}` with a bare `<name>.test`, so the RSS feed (and sitemap/canonical links) of every new project had links like `demo.test/blog/...` without a scheme. It came up while checking the with_blog RSS output.

## Options considered
- Fix here: one line in mkdox2.sh, fixes every template.
- Separate item: keeps this item to the blog only.

## Decision
mkdox2 new fills site_url with https://<name>.test/

## Consequences
`{SITE_URL}` becomes `https://<name>.test/` (with a trailing slash). Users still need to put their real domain in `site_url` before publishing.

> Superseded by decisions/2026-11-01.site-url-is-the-bare-host.md: putting `https://` into `{SITE_URL}` broke the 5 templates that already wrote `http://{SITE_URL}` and the content that uses `{SITE_URL}` as a host name.
