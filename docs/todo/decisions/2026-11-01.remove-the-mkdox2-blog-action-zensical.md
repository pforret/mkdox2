# Remove the mkdox2 blog action; Zensical's blog plugin generates the index, archive and categories

## Context
`mkdox2 blog` was written before Zensical had a built-in blog (confirmed by the user). With Zensical 0.0.74's native blog, running it and then building shows a hand-made post list (with mangled excerpts) above the plugin's own list, and creates `/blog/categories/*` next to the plugin's `/blog/category/*`.

## Options considered
- Remove it: simplest, no duplication; old `mkdocs.yml` projects without the Material blog plugin lose the helper.
- Print a message for `zensical.toml` projects, keep the old behaviour for `mkdocs.yml`: keeps two code paths alive.
- Keep it but stop writing index/categories/tags: almost nothing left to do.

## Decision
Remove the mkdox2 blog action; Zensical's blog plugin generates the index, archive and categories

## Consequences
The blog index, archive and category pages come only from `[project.plugins.blog]`. `docs/blog/index.md` is a plain entry point. `mkdox2 post` stays the way to create posts. The usage text in README.md/docs/index.md drops the `mkdox2 blog` lines when it is regenerated.
