# mkdox2 error-path tests check the error message and side effects, not the exit code

## Context
The PRP for the template-menu item suggested `assert_fails` for the new error-path tests (invalid choice, unknown `-B`). While implementing, `IO:die` turned out to exit with status 0 (`Script:exit` always does `exit 0`), so `assert_fails` failed even though the script stopped correctly.

## Options considered
- `assert_fails` on the exit code, as in the spec: impossible without fixing `IO:die`/`Script:exit`, which changes the exit code of all 37 `IO:die` calls (out of scope).
- Check the error message (`grep -c`) and that no project folder was created: tests what the item promises, works today.

## Decision
mkdox2 error-path tests check the error message and side effects, not the exit code

## Consequences
Error-path tests in tests/test_basic.sh assert on output and side effects. Once `IO:die` exits non-zero, these tests can be tightened with `assert_fails`.
