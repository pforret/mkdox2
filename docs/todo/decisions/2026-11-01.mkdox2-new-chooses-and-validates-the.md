# mkdox2 new chooses and validates the template before Docker or mkdir

## Context
Planning the template-menu item (request: "default template should be: simple site, then site + blog, then Karpathy wiki and that's it"). The menu ran only after `Docker:require_running`, `mkdir` and Docker's `zensical new`, so a typo or Ctrl-C left a half-made project.

## Options considered
- Choose and validate first: nothing is created on a bad choice; the menu and errors can be tested without Docker.
- Keep the current order: smallest diff, but half-made projects stay possible.

## Decision
mkdox2 new chooses and validates the template before Docker or mkdir

## Consequences
The template block sits at the top of the `new)` action and may only use `$script_install_folder` (not `$folder_path`, which exists later). bash_unit tests for the menu and for invalid choices run without a Docker daemon.
