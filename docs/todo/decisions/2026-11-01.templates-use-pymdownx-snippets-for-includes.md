# Templates use pymdownx.snippets for includes, not markdown-include or include-markdown

## Context
Planning "Add Zensical plugins to the templates" (request: add llmstxt, tags, glightbox, privacy, minify, social, callouts, markdown-include). Testing showed `markdown-include` (`{!file.md!}`) is not loaded by Zensical: the tag stays as literal text, with no error.

## Options considered
- Native `include-markdown` plugin (`{% include-markdown "file.md" %}`): tested, works; one more plugin.
- Only `pymdownx.snippets` (`--8<-- "file.md"`): already enabled in every template, tested, works; less familiar syntax.
- Both.

## Decision
Templates use pymdownx.snippets for includes, not markdown-include or include-markdown

## Consequences
Includes in templates and docs use `--8<-- "path"` (pymdownx.snippets). No include plugin is configured. The `markdown-include` pip package in docker/Dockerfile is dead and goes in a later image update.
