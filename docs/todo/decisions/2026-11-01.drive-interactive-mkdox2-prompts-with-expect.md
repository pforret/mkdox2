# Drive interactive mkdox2 prompts with expect in manual tests, not piped into script

## Context
The PRP's manual check fed the template choice with `printf '3\n' | script -q /dev/null mkdox2 new …` (`script` gives `docker run -it` a TTY). The piped answer got lost and `read` saw an empty line, so choice 3 silently became the default `simple`.

## Options considered
- `script` + pipe, as in the spec: unreliable on macOS; with an Enter default, a lost answer looks like success.
- `expect` (`spawn mkdox2 new …; expect "Pick a template"; send "3\r"; expect eof`): real TTY and a real answer to the prompt; needs `expect` installed (it comes with macOS).

## Decision
Drive interactive mkdox2 prompts with expect in manual tests, not piped into script

## Consequences
Manual or integration checks of `mkdox2` prompts that also run Docker with `-it` should use `expect`. Plain pipes are fine only for paths that stop before Docker (as the bash_unit tests do).
