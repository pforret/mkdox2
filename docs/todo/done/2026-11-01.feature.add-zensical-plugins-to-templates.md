# Add Zensical plugins to the templates

## Request
add llmstxt, tags, glightbox, privacy, minify, social, callouts, markdown-include to templates

## Analysis
Today every template enables only `[project.plugins.search]`; with_blog also has `blog` and `rss`.
The Zensical plugin page (https://zensical.org/docs/compatibility/mkdocs/plugins/) lists all eight
requested names except `markdown-include` as natively supported. Plugins that aren't on its list are
silently ignored, and supported plugins reject unknown settings with a configuration error. This is
net-new capability, so it's a `feature`. It's `large`: 6 `zensical.toml` files plus example content
and docs, and it can only be checked with a Docker build per template.

Per plugin (since = Zensical version that added it; the image runs 0.0.74):
- **llmstxt** (0.0.67): generates `llms.txt` plus Markdown copies of selected pages. With
  `content.action.copy` in `theme.features`, a "Copy as Markdown" button appears. Strong fit for
  karpathy_wiki and ai_employee, which are LLM-oriented. Needs a decision on which pages/sections go in.
- **tags** (0.0.58): front-matter `tags:` plus tag listing pages. Zensical silently ignores some
  legacy settings (see the "Differences" on the plugin page). No template content has `tags:` yet;
  it only becomes visible once a few pages get tags and a tags index page exists.
- **glightbox** (0.0.35): image lightbox. Some settings are ignored (touchNavigation, loop, effect,
  …). No template has content images (only favicons in `docs/icon/`), so nothing shows until users
  add images. It's still harmless to enable.
- **privacy** (0.0.72): self-hosts external assets and annotates external links. The templates load
  Google Fonts (`[project.theme.font] text = "Nunito"`), so this removes a third-party request (GDPR),
  but the build then needs network access to download them.
- **minify** (0.0.58): smaller HTML/JS/CSS. Makes `serve` output harder to debug; consider
  enabling it only for builds (if Zensical supports that) or just leave it always on.
- **social** (0.0.67): social cards and Open Graph tags. It needs `site_url`, which `mkdox2 new`
  now fills with `https://<name>.test/` (item "check with_blog"). Risk: in MkDocs Material it needs
  Cairo/Pillow, and the Alpine-based `pforret/mkdox-zensical` has no `cairosvg` (`ModuleNotFoundError`).
  Zensical's version may be native. Test a build before enabling it; it may also slow builds down.
- **callouts** (0.0.62): Obsidian-style `> [!note]` callouts rendered as admonitions (it turns on
  `pymdownx.quotes` with `callouts: true`; its 3 settings are ignored). Good fit for karpathy_wiki.
  The closely related **gh-admonitions** handles GitHub-style alerts.
- **markdown-include**: not a plugin but a Python-Markdown extension (`markdown_include.include`,
  `{!file.md!}` syntax). Its pip package `markdown-include` is already in `docker/Dockerfile`. It
  isn't on Zensical's plugin list. Whether Zensical loads arbitrary installed Markdown extensions
  under `[project.markdown.extensions]` must be tested. The natively supported alternatives are
  **include-markdown** (0.0.71, `{% include-markdown "file.md" %}`) and `pymdownx.snippets`, which is
  already enabled in the templates.

**Tested during planning** (scratch copy of a with_blog project, `pforret/mkdox-zensical` = Zensical 0.0.74):
- Works with default settings: `glightbox` (lightbox assets self-hosted under `assets/external/unpkg.com/glightbox@3`), `privacy` (Google Fonts, twemoji, avatar and dummyimage downloaded to `site/assets/external/`), `social` (`site/assets/images/social/*.png` + `og:image` = `https://demo.test/assets/images/social/index.png`; no Cairo needed), `callouts` (`> [!NOTE]` → `<div class="admonition note">`).
- Needs settings: `llmstxt` without `sections` builds silently but gives a header-only `llms.txt` (sections are "Required"). With `sections` + `full_output` it gives `llms.txt`, `llms-full.txt` and Markdown copies; `content.action.copy` adds the "Copy as Markdown" button. `minify` does nothing by default; `minify_html = true` (+ inline JS/CSS) makes `index.html` a single line (24 KB → 18 KB). `tags` shows tags on pages, but a listing needs a page with `<!-- material/tags -->`.
- **`markdown-include` doesn't work**: `{!inc/part.md!}` stays literal text, with no error. `pymdownx.snippets` (`--8<-- "inc/part.md"`, already enabled in every template) and native `include-markdown` both work.
- Build with everything on: ~4.4 s the first time (downloads), 0.4 s cached. With the cache in place, `docker run --network none … build` also works. `mkdox2 serve` + hot-reload works with all plugins on.
- Stale content found: `about/features/plugins.md` (simple, with_blog) still lists awesome-pages and with-pdf, and `docs/index.md` (simple, with_blog) says "run `mkdox serve`".
- New projects get no `.gitignore` (only `templates/.gitignore`, outside the template folders, exists), so `site/` and `.cache/` (privacy/social cache) would end up in git.

All open questions were settled during planning (see PRP, Decisions taken).

## PRP

### Goal
Every template ships the same set of natively supported Zensical plugins: llmstxt, tags, glightbox,
privacy, minify, social and callouts. Each has settings that make it visibly work, plus small example
content (a tags index, tagged pages, a callout). New projects get a `.gitignore` for `site/` and
`.cache/`, and the stale plugin page and `mkdox serve` hints are fixed. Includes use the already
enabled `pymdownx.snippets`; markdown-include is not used.

### Why
- The templates use almost none of Zensical's built-in plugins, while several are a clear win for every site: self-hosted fonts (GDPR), link previews, smaller pages, `llms.txt` for AI readers.
- Two templates (karpathy_wiki, ai_employee) are about AI-maintained knowledge; `llms.txt` and "Copy as Markdown" fit them directly.
- Users copy what the templates show; dead or misleading content (awesome-pages, with-pdf, `mkdox serve`) misleads them.

### Decisions taken
- Which templates → all 7 plugins in all 6 templates; only llmstxt `sections` differ per template (user) (recorded: decisions/2026-11-01.all-templates-enable-llmstxt-tags-glightbox.md)
- Includes → only `pymdownx.snippets` (`--8<--`), no include-markdown plugin, no markdown-include (user) (recorded: decisions/2026-11-01.templates-use-pymdownx-snippets-for-includes.md)
- Example content → small: `docs/tags.md` index, `tags:` on 2-3 existing pages, one callout per template, updated plugins page (user) (recorded: decisions/2026-11-01.templates-ship-small-example-content-for.md)
- privacy + social → both on by default (user) (recorded: decisions/2026-11-01.privacy-and-social-plugins-are-on.md)
- privacy assets → only Google Fonts + glightbox via `assets_include` (user, during implementation) (recorded: decisions/2026-11-01.privacy-self-hosts-only-google-fonts.md)
- minify settings → `minify_html`, `minify_inline_js`, `minify_inline_css` = true (default) (recorded: decisions/2026-11-01.minify-runs-with-minify-html-minify.md)
- llmstxt settings → `sections` from each template's top-level folders, `full_output = "llms-full.txt"`, plus `content.action.copy` in `theme.features` (default) (recorded: decisions/2026-11-01.llmstxt-sections-follow-each-template-s.md)
- `.gitignore` in each template with `site/` and `.cache/` → yes (default; needed because of the privacy/social cache)
- Removing `markdown-include` (and the other dead pip packages) from docker/Dockerfile → not in this item; next image update (default) (recorded: decisions/2026-11-01.dead-pip-packages-leave-the-docker.md)

### Known gotchas & guardrails
- Mirror the existing patterns named under Context; do not introduce new ones for this item
- CRITICAL: TOML: llmstxt sections are a sub-table, e.g. `[project.plugins.llmstxt.sections]` then `"Docs" = ["index.md", "about/*.md"]`, and it must come after the `[project.plugins.llmstxt]` keys (`full_output = …`). A glob like `about/*.md` also matched `about/features/*.md` in the test; check each `llms.txt` lists the pages you expect.
- CRITICAL: section globs must match files that exist in that template (see `ls templates/<t>/docs`); a section with no matches gives an empty heading.
- CRITICAL: the first build needs network (privacy downloads from fonts.gstatic.com, unpkg.com, cdn.jsdelivr.net, github.com, dummyimage.com); later builds use `.cache/`. Don't run the validation with `--network none` on a fresh project.
- PRESERVE: existing plugin blocks (search, blog, rss + rss.date_from_meta), extensions, palette, analytics/consent settings; `{PLACEHOLDER}` names
- PRESERVE: `docs/blog/index.md`, post front matter, `.authors.yml` in with_blog (from the previous item)
- `tags:` front matter: add it below the existing keys; pages without front matter get a new `---` block at the very top (keep `# Title` lines below it)
- The callout uses Obsidian syntax `> [!NOTE]` + `> text`; put it on a page that exists in every template (`docs/index.md` is fine) or a better-fitting page per template
- Don't touch mkdox2.sh, tests or docker/Dockerfile for this item
- Also update: docs/zensical/compatibility.md (the 7 plugins tested on 0.0.74 + markdown-include not working) and CHANGELOG.md

### Approach
Do with_blog first (it has the most plugins already) and get it fully passing, then copy the same
block into the other five `zensical.toml` files, changing only the llmstxt `sections`. Per template:
add `docs/tags.md`, `tags:` on 2-3 pages that fit (e.g. committee decisions/topics, karpathy_wiki
concepts/entities, dev_project ADRs, blog posts), one callout, and `.gitignore`. Then rewrite the
two `plugins.md` pages, fix the `mkdox serve` hint, and update the docs and CHANGELOG. Validate all
six templates with the loop below.

### Validation loop (executable, in order)
```bash
# Level 1 — config sanity
for t in templates/*/; do for p in llmstxt tags glightbox privacy minify social callouts; do grep -q "^\[project.plugins.$p\]" $t/zensical.toml || echo "MISSING $p in $t"; done; done   # expect no output
grep -rlE 'markdown_include|markdown-include|awesome-pages|with-pdf|mkdox serve' templates   # expect no match
ls templates/*/.gitignore templates/*/docs/tags.md | wc -l                                   # expect 12
# Level 2 — repo tests (unchanged code)
./tests/run_tests.sh && shellcheck -S warning mkdox2.sh                                      # expect all ok, no output
# Level 3 — build every template (Docker, needs network for the first build)
T=$(mktemp -d); cd "$T"
for t in simple with_blog karpathy_wiki ai_employee committee dev_project; do
  script -q /dev/null /Users/pforret/Code/mkdox/mkdox2/mkdox2 -B $t new d_$t </dev/null >/dev/null 2>&1
  (cd d_$t && script -q /dev/null /Users/pforret/Code/mkdox/mkdox2/mkdox2 build </dev/null > ../b_$t.log 2>&1)
  s=d_$t/site
  echo "$t: llms=$(grep -c '^## ' $s/llms.txt) full=$(test -f $s/llms-full.txt && echo y) tags=$(grep -c 'md-tag' $s/tags/index.html) min=$(wc -l < $s/index.html | tr -d ' ') ext=$(ls $s/assets/external | wc -l | tr -d ' ') social=$(test -f $s/assets/images/social/index.png && echo y) og=$(grep -c 'og:image' $s/index.html) callout=$(grep -rl 'admonition' $s --include=index.html | wc -l | tr -d ' ') copy=$(grep -c 'md-content__button' $s/index.html) gi=$(grep -c -E '^(site|\.cache)/' d_$t/.gitignore)"
  grep -iE 'error|warn' b_$t.log | head -3
done
# expect per template: llms>=1 full=y tags>=1 min<=1 ext>=1 social=y og>=1 callout>=1 copy>=1 gi=2, and no error lines
# serve (manual): cd d_karpathy_wiki && mkdox2 serve → page loads, edit a page → hot-reload; Ctrl-C
```
