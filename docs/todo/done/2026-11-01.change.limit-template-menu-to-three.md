# Limit template menu to simple, blog, Karpathy wiki

## Request
default template should be: simple site, then site + blog, then Karpathy wiki and that's it

## Analysis
When `mkdox2 new` runs without `-B/--TEMPLATE`, `mkdox2.sh:96-119` lists every folder under
`templates/*/` in glob (alphabetical) order and asks for a number. With six template folders the
menu is `1) ai_employee 2) committee 3) dev_project 4) karpathy_wiki 5) simple 6) with_blog`.
The request is a fixed menu `1) simple 2) with_blog 3) karpathy_wiki` and nothing else. The menu
also currently runs only after Docker's `zensical new` has created the folder. All open questions
were settled during planning (see PRP, Decisions taken).

## Impacted files
- `mkdox2.sh`: `new` action: template choice moved before `Docker:require_running`/folder creation; fixed 3-item menu; Enter = simple
- `tests/test_basic.sh`: bash_unit tests for the menu (contents/order, Enter default, invalid choice, unknown -B), no Docker needed
- `CLAUDE.md`: "Template system" line: menu templates and the hidden ones

## Plan
See the PRP below.

## Acceptance criteria
- `mkdox2 new demo` without `-B` shows exactly `1) simple`, `2) with_blog`, `3) karpathy_wiki`, in that order, each with its `description.txt` line; no other templates listed
- Typing 1/2/3 uses that template; pressing Enter uses `simple`
- An invalid choice or an unknown `-B` name stops with an error **before** any folder is created or Docker runs
- `mkdox2 -B dev_project new demo` (and `ai_employee`, `committee`) still works
- `shellcheck -S warning mkdox2.sh` clean; `./tests/run_tests.sh` passes with the new tests

## PRP

### Goal
`mkdox2 new` without `-B` offers a fixed menu `1) simple  2) with_blog  3) karpathy_wiki` (with
descriptions), Enter picks `simple`, and the template is chosen and validated before any folder is
created or Docker runs. `ai_employee`, `committee` and `dev_project` stay in `templates/` and keep
working through `-B <name>`, but are not listed.

### Why
- Six alphabetical choices put niche templates first; most new projects want a plain site, a site with a blog, or a Karpathy-style wiki.
- Enter-for-simple makes the common case one keystroke.
- Today a typo at the prompt leaves a half-made project (folder + `zensical new` output) behind.

### Decisions taken
- Other templates (ai_employee, committee, dev_project) → hidden from the menu, still usable with `-B <name>`, not deleted (user) (recorded: decisions/2026-11-01.hide-ai-employee-committee-and-dev.md)
- Empty answer at the prompt → `simple` (choice 1); prompt shows the range and the default (user) (recorded: decisions/2026-11-01.enter-at-the-template-prompt-picks.md)
- Where the order lives → hardcoded array in mkdox2.sh, e.g. `local menu_templates=(simple with_blog karpathy_wiki)` (user) (recorded: decisions/2026-11-01.template-menu-order-is-a-hardcoded.md)
- When to ask → choose and validate the template first, before `Docker:require_running`, `mkdir` and `docker run … new` (user) (recorded: decisions/2026-11-01.mkdox2-new-chooses-and-validates-the.md)
- Prompt wording → `Pick a template [1-3, Enter=1] > ` (default)
- A menu template missing on disk → `IO:die` with the same "not found" message as `-B` (default)

### Known gotchas & guardrails
- Mirror the existing patterns named under Context; do not introduce new ones for this item
- CRITICAL: the template choice must come before `Docker:require_running` too, so the new tests run without a Docker daemon (CI ubuntu runner, tests/run_tests.sh). `Os:require "docker"` at line 69 only checks the binary and stays.
- CRITICAL: `read -r -p` from a pipe prints no prompt; tests feed choices with `printf '2
' | "$root_script" new demo`. A valid choice in a test then continues into Docker, so tests should only check invalid choices/unknown -B (they exit before Docker) and the printed menu (with input `x` → dies, the menu is printed first).
- PRESERVE: `-B <name>` / `TEMPLATE` from `.env` skips the menu and is validated against `$script_install_folder/templates/$TEMPLATE/` exactly as today; hidden templates must still pass.
- PRESERVE: everything after the template choice (`zensical new`, the cleanup of `.github`/`mkdocs.yml`, placeholder substitution, final hints) is unchanged.
- PRESERVE: `$folder`/`folder_path` handling. `folder_path` is computed after `mkdir`, so the template code at the top must only use `$script_install_folder`, not `$folder_path`.
- Also update: CLAUDE.md "Template system" line (lists only simple and with_blog).

### Approach
Only `mkdox2.sh`, `tests/test_basic.sh` and `CLAUDE.md` change. In the `new)` action, move the
template block to the very top (before `Docker:require_running`): if `TEMPLATE` is empty, print the
3 entries from the hardcoded `menu_templates` array with their description lines, read the choice
(empty → 1), and map it to the name or `IO:die "Invalid choice: …"`; then do the existing
`template_folder` existence check. Delete the old glob loop at 96-119 and the old check at 120-122.
The rest of the action runs as before with `$TEMPLATE`/`$template_folder` already set.
Add bash_unit tests that run in a temp dir and cover: the menu lists exactly the 3 names in order
and none of the hidden ones; an invalid choice dies and creates no folder; an unknown `-B` dies and
creates no folder.

## Notes
- Discovery: `IO:die` → `Script:exit` always ends with `exit 0` (mkdox2.sh, `Script:exit`), so all 37 `IO:die` calls return status 0. That's out of scope here; it would change exit codes everywhere and is worth its own item.
- Deviation: because of that, the two error-path tests don't use `assert_fails` as the PRP suggested. They check the error message (`Invalid choice: 9` / `Template 'nope' not found`) and that no `demo/` folder was created.
- Gotcha: `printf '3\n' | script -q /dev/null mkdox2 new …` loses the piped answer, so `read` sees an empty line (it silently became `simple`). Level 3 used `expect` (`spawn …; expect "Pick a template"; send "3\r"`) instead; the PRP's residual risk came true.


## Result

### Verification
- Menu: `printf 'x\n' | mkdox2 new demo` (temp dir) → exactly `1) simple`, `2) with_blog`, `3) karpathy_wiki` with their `description.txt` lines; no ai_employee/committee/dev_project
- Choices (real runs with Docker, driven by `expect`): `1` → simple, `2` → with_blog, `3` → karpathy_wiki, Enter (`printf '\n'`) → simple; each created a full project
- Nothing created on error: `test_new_invalid_choice_creates_nothing` and `test_new_unknown_template_creates_nothing` → "Invalid choice: 9" / "Template 'nope' not found", no `demo/`; the menu block (`menu_templates=`, line 81) runs before `Docker:require_running`
- Hidden templates still work: `mkdox2 -B dev_project new d_dev` → "Use template: dev_project", project created
- `shellcheck -S warning mkdox2.sh tests/test_basic.sh` → clean; `grep -c 'templates/\*/' mkdox2.sh` → 0
- `./tests/run_tests.sh` → 5/5 ok (2 existing + 3 new)

### Deviations from the spec
- The error-path tests check the error message and the missing folder, not the exit code with `assert_fails` as the PRP suggested, because `IO:die` exits with status 0. (recorded: decisions/2026-11-01.mkdox2-error-path-tests-check-the.md)
- Level 3 used `expect` instead of piping into `script -q /dev/null`, which loses the piped answer. (recorded: decisions/2026-11-01.drive-interactive-mkdox2-prompts-with-expect.md)
- Small addition: a `#TIP:> $script_prefix -B dev_project new <name>` usage line, so the hidden templates can be found from the help. (recorded: decisions/2026-11-01.show-a-b-usage-example-for.md)

### Discoveries
- `IO:die` → `Script:exit` always ends with `exit 0` (mkdox2.sh, `Script:exit`): all 37 `IO:die` calls report success to the caller, so scripts/CI can't detect mkdox2 failures. Worth its own bug item.
- Piping answers through `script -q /dev/null` loses them: `read` sees an empty line, so with Enter=simple a wrong choice looks like success (logged in gotchas.md).
- Both CI workflows (`.github/workflows/bash_unit.yml`, `shellcheck.yml`) trigger only on `master`, but the branch is `main`, so the new tests and shellcheck never run in CI.
