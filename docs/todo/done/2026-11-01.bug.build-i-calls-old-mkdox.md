# build -I calls the old mkdox tool

## Request
build -I calls the old mkdox tool.

## Analysis
`mkdox2 build -I` (mkdox2.sh ~204-225) creates `index.md` in every docs folder that has an
`index.pre`/`index.post` (the simple and with_blog templates have `docs/about/index.pre` + `.post`).
For each folder it runs `mkdox -R -Q toc . index.md` (blog folders) or `mkdox -R -T toc . index.md`,
which is the **old MkDocs-based `mkdox`** tool from the PATH (`~/.basher/cellar/bin/mkdox`), not
mkdox2. Where `mkdox` isn't installed, `-I` fails; where it is, the TOC comes from another tool and
version. A `bug` (retyped from change).

Fix: call this script itself: `"$script_install_path" -R -Q toc . index.md` (bashew sets
`script_install_path`, following symlinks). mkdox2's `toc` supports `-R`, `-Q`, `-T` and fills in
`<name>.pre`/`.post` around the TOC when an output file is given. The help text of flags `-Q`, `-R`,
`-T` (lines 43-45) and option `-H` (line 51) also says "for mkdox toc/recent".

## Impacted files
- `mkdox2.sh`: the 2 calls in `build` (`-I` block), the help text on lines 43-45 and 51

## Plan
