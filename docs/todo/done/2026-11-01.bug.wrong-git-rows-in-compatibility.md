# Wrong git-* rows in compatibility.md

## Request
The wrong git-* rows in compatibility.md.

## Analysis
`docs/zensical/compatibility.md` ("Plugin Compatibility" table) was written from an older summary
and disagrees with Zensical's plugin page (https://zensical.org/docs/compatibility/mkdocs/plugins/,
checked against Zensical 0.0.74):
- `git-revision-date-localized`, `git-authors`, `git-committers`: listed as "Native built-in", but
  the page lists them under **Compatibility roadmap → Planned**. Not supported yet.
- `mkdocstrings`: "Replaced by dedicated API documentation module (in development)", but it's
  supported natively since 0.0.11 (needs `pip install mkdocstrings-python`).
- `macros`: "Replaced by built-in component system", but the macros plugin is supported since 0.0.40.
- `minify`: "+ image compression" isn't part of it; image optimisation (`optimize`) is "In progress".
- `mike`: supported since 0.0.30, but needs Zensical's compatible fork.
- `static-i18n`: not on the page at all, so not supported.
- The closing line "Other plugins not listed above are not loaded" suggests the table is the full
  list, but the page supports about 30 plugins (llmstxt, tags, social, privacy, …).
A `bug`: the docs state wrong facts.

## Impacted files
- `docs/zensical/compatibility.md`: the Plugin Compatibility table and the line under it

## Plan
1. [x] Rewrite the table from the plugin page: 17 rows with status (native since x.y.z / planned / in progress / not supported) and notes
2. [x] Intro points to the page as the full list (~30 native plugins); keeps "unsupported plugins are silently ignored" and adds "unknown settings are a configuration error"
3. [x] "Plugins used in the mkdox2 templates" section unchanged

## Acceptance criteria
- No row claims git-revision-date-localized, git-authors or git-committers are supported
- Each row's status matches the Zensical plugin page (since-version where it gives one)
- The page links to the official list for everything not in the table

## Notes
- Also fixed in the Features table: "revisioning" was listed as Supported; it's now a separate row "Revision dates/authors from git … Planned", since the git-* plugins are only planned.
- Added rows the table was missing but people ask about: `gen-files` and `open-in-new-tab` (the page's two explicitly unsupported plugins), `markdown-include` (tested, not loaded), `include-markdown`, `meta`.
- `https://zensical.org/compatibility/` (the source cited at the top of the page) returned nothing usable to curl; all statuses come from the plugin page.


## Result

### Verification
- `grep -E 'git-(revision|authors|committers)' docs/zensical/compatibility.md | grep -vci planned` → 0: no row claims they're supported (Features table and plugin table both say Planned)
- Since-versions match the Zensical plugin page: search 0.0.3, mkdocstrings 0.0.11, mike 0.0.30, macros 0.0.40, awesome-nav/literate-nav/meta/minify 0.0.58, blog 0.0.64, rss 0.0.65, include-markdown 0.0.71 (8/8 greps ok); optimize In progress; gen-files/open-in-new-tab Not supported, as on the page
- The page links to https://zensical.org/docs/compatibility/mkdocs/plugins/ as the full list (2 references)

### Deviations from the spec
- Scope widened from "the git-* rows" to the whole table: mkdocstrings, macros, minify, mike and static-i18n were wrong too, plus the "revisioning: Supported" claim in the Features table. (recorded: decisions/2026-11-01.docs-zensical-compatibility-md-follows-zensical.md)

### Discoveries
- `https://zensical.org/compatibility/`, the source cited at the top of compatibility.md, returned nothing usable to curl (probably moved or rendered by JS); the plugin page is the reliable source.
- The plugin page's statuses change per Zensical release (several plugins were added between 0.0.58 and 0.0.72), so this table goes stale with every image update.

### Changes
- `docs/zensical/compatibility.md`: plugin table rewritten (17 rows + intro), Features table "revisioning" row split into a Planned row
