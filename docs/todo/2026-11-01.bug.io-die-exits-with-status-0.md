# IO:die exits with status 0

## Request
IO:die exits with status 0: every failure in mkdox2 looks like success to scripts and CI.

## Analysis
`IO:die` (mkdox2.sh ~line 746) prints the error to stderr, rings the bell and calls `Script:exit`.
`Script:exit` (~line 978) cleans up temp files, clears the trap and always ends with `exit 0`. So
all 37 `IO:die` calls report success. That includes "No zensical.toml or mkdocs.yml found",
"Could not create new Zensical project", "Invalid choice", "Template … not found" and the
error/EXIT trap (~line 972, `trap "IO:die \"ERROR \$? …\"" INT TERM EXIT`), which even prints the
real failing status `$?` and then exits 0. `mkdox2 build && deploy` would deploy after a failed
build, and CI can't detect failures.

The bug comes from the bashew framework: upstream `pforret/bashew` `template/script.sh` has the same
`IO:die` → `Script:exit` → `exit 0` chain (lines 278/641 at HEAD).

Likely fix: `Script:exit` takes an optional status (`exit "${1:-0}"`) and `IO:die` calls
`Script:exit 1`. The other `Script:exit` callers stay at 0: the usage screen without parameters,
skipping the git commit in `build`, and the help path in `Option:parse`. The test
`test_no_parameters_shows_usage` expects exit 0, so the usage screen must stay at 0.

Watch out:
- `Gha:finish` (~line 958) ends with a plain `exit 0` without clearing the trap. The EXIT trap then
  runs `IO:die`, which exits 0 today and would exit 1 after the fix. That turns its success into a
  failure (and it probably already prints a bogus "ERROR 0" message). It needs `trap - INT TERM EXIT`
  before the exit, or `Script:exit`.
- In the EXIT trap, `IO:die` could pass the original `$?` through instead of 1, so the real status
  is kept. That's optional.
- Any caller that relied on mkdox2 "never failing" will now see failures. That's the point, but
  it's worth a CHANGELOG line.

Open questions:
- Should the trap keep the original `$?` (more precise) or always return 1 (simpler)?
- Fix it upstream in bashew too? That's a separate repo and outside this item; maybe a follow-up.

## Impacted files
- `mkdox2.sh`: `Script:exit` takes an optional status, `IO:die` uses `Script:exit 1`, `Gha:finish` clears the trap before its `exit 0`
- `tests/test_basic.sh`: tighten `test_new_invalid_choice_creates_nothing` / `test_new_unknown_template_creates_nothing` to `assert_status_code 1` (their comments name this bug); add a test that a missing config fails `build` with a non-zero status
- `CHANGELOG.md`: note that failures now exit non-zero

## Plan
1. `Script:exit`: `exit "${1:-0}"`; `IO:die`: `Script:exit 1` (or pass on the trap's `$?`).
2. `Gha:finish`: clear the trap before `exit 0`.
3. Check every `Script:exit` call site (~lines 242, 246, 1186, 1236, 1615) still means success.
4. Tests: the two `new` error tests assert status 1; new test: `mkdox2 build` in an empty temp dir → status 1 + "No zensical.toml or mkdocs.yml found"; the usage test still passes with 0.
5. CHANGELOG entry.

## Acceptance criteria
- `printf '9\n' | mkdox2 new demo; echo $?` → `1`; `mkdox2 -B nope new demo </dev/null; echo $?` → `1`
- `mkdox2 build` in a folder without config → status 1
- `mkdox2` without parameters (usage) → status 0; a successful `mkdox2 build` → status 0
- `./tests/run_tests.sh` passes, including the tightened tests; `shellcheck -S warning mkdox2.sh` clean
